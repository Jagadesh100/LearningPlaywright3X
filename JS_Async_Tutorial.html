1️⃣ Callback JS

What is it? A function passed as an argument to another function, which calls it later. The receiving function decides when to invoke it.

// Passing a function as an argument, called later
function greeting(greet, callback) {
  console.log("Hello");
  callback();              // ← the "later" part
}

function printName() {
  console.log("UserName");
}

greeting("Good", printName); // pass the reference, NO parentheses
Key rule: pass printName without parentheses. printName() would execute immediately and pass undefined instead.

Flow Diagram

┌──────────────────────────────────────────────┐ │ greeting("Good", printName) → CALL SITE │ │ "Good" → greet (string) │ │ printName → callback (function ref) │ └──────────────────────┬───────────────────────┘ │ call begins ▼ ┌──────────────────────────────────────────────┐ │ function greeting(greet, callback) │ │ 1. console.log("Hello") → "Hello" │ │ 2. callback() ◄── invokes printName │ └──────────────────────┬───────────────────────┘ ▼ ┌──────────────────────────────────────────────┐ │ function printName() │ │ 3. console.log("UserName") → "UserName"│ └──────────────────────────────────────────────┘ Output: Hello UserName

Why callbacks matter

  • They let you pass behavior into a function.
  • They are the foundation of all async code (setTimeout, event handlers, array methods).
  • Nesting too many callbacks creates Callback Hell / Pyramid of Doom — the problem Promises solve.
Playwright: test("has title", async ({ page }) => {...}) — the arrow function is a callback that Playwright calls for you. Locator actions are callback-driven too.

2️⃣ new Promise JS

What is it? A constructor that creates an object representing the eventual completion or failure of an async operation. It takes an executor function with two parameters: resolve and reject.

let apiCall = new Promise(function (resolve, reject) {
  // pretend an API request happened...
  let success = true;
  if (success) {
    resolve({ status: 200, body: "User Data" });  // → fulfilled
  } else {
    reject({ status: 500 });                                // → rejected
  }
});

apiCall
  .then(function (res) { console.log("OK:", res.status, res.body); })
  .catch(function (err) { console.log("Failed:", err.status); })
  .finally(function () { console.log("Cleanup always runs"); });

Promise Lifecycle

┌─────────────────────────────────────────────┐ │ new Promise(executor) │ └──────────────────────┬───────────────────────┘ ▼ ┌─────────────────────────────────────────────┐ │ PENDING (work in progress) │ └──────────────────────┬───────────────────────┘ ┌───────┴────────┐ ▼ ▼ ┌─────────────────────┐ ┌─────────────────────┐ │ resolve(value) │ │ reject(reason) │ │ → FULFILLED │ │ → REJECTED │ │ .then() runs │ │ .catch() runs │ └─────────────────────┘ └─────────────────────┘ └──────────┬──────────┘ ▼ ┌─────────────────────────────────────────────┐ │ .finally() — ALWAYS runs (either path) │ └─────────────────────────────────────────────┘ A promise settles ONCE. After fulfilled/rejected, it can never change state again.
Warning: a rejected promise with no .catch() produces an unhandled promise rejection — your test can fail or the process can crash.

Three important behaviors

  • .then() runs on resolve; .catch() runs on reject; .finally() always runs.
  • Returning a value from .then() passes it to the next .then() — this is chaining.
  • Returning a promise from .then() makes the next .then() wait for it — sequential async flow.

3️⃣ async JS

What is it? A keyword that marks a function as asynchronous. An async function always returns a Promise — even if you return a plain value, it gets wrapped.

async function getUser() {
  return "UserName";   // plain value → wrapped in a resolved promise
}

console.log(getUser());  // Promise {<fulfilled>: "UserName"} — NOT the string

getUser().then(function (name) {
  console.log("Got:", name);  // must use .then() or await to get the value
});
Rule: async functions always return a promise. To get the value, you need .then() or await. This is why async () => {...} is the standard shape of every Playwright test.

Flow Diagram

┌──────────────────────────────────────────────┐ │ async function getUser() { │ │ return "UserName"; │ │ } │ └──────────────────────┬───────────────────────┘ │ call getUser() ▼ ┌──────────────────────────────────────────────┐ │ return value "UserName" │ │ │ │ │ └──► wrapped automatically │ │ into Promise.resolve("UserName") │ └──────────────────────┬───────────────────────┘ ▼ ┌──────────────────────────────────────────────┐ │ Promise { <fulfilled>: "UserName" } │ │ │ │ │ ├──► .then(name => ...) gets value │ │ └──► await getUser() gets value │ └──────────────────────────────────────────────┘

4️⃣ await JS

What is it? A keyword that pauses execution of an async function until a promise settles, then resumes with the resolved value. It can only be used inside an async function.

function fetchData() {
  return new Promise(function (resolve) {
    setTimeout(function () {
      resolve("API response");
    }, 1000);   // simulate 1s network delay
  });
}

async function main() {
  console.log("1. Calling API...");
  let data = await fetchData();   // ← pauses here ~1s
  console.log("2. Got:", data);
  console.log("3. Done");
}

main();
Common pitfall: forgetting await in Playwright (page.click() without await) — the action is scheduled but the test moves on before it finishes, causing flaky tests.

await vs .then()

SAME result, TWO styles: ┌── .then() style ─────────────────────────────┐ │ fetchData().then(data => { │ │ console.log(data); │ │ }); │ └─────────────────────────────────────────────┘ ┌── await style (inside async fn) ────────────┐ │ let data = await fetchData(); │ │ console.log(data); │ └─────────────────────────────────────────────┘ await = "pause here, then give me the value" .then = "call me back later with the value" Both are equivalent — await is just cleaner to read.
Error handling: await + try/catch replaces .catch(): 
try {
  let data = await fetchData();
} catch (err) {
  console.log("Failed:", err);
}

5️⃣ Promise.all JS

What is it? Takes an array of promises, runs them in parallel, and resolves with an array of ALL values — only if every promise resolves. If any rejects, it rejects immediately (fail-fast).

let checkAuth   = Promise.resolve("Auth Ok");
let checkDB     = Promise.resolve("DB Ok");
let checkCache  = Promise.resolve("Cache Cleared");

Promise.all([checkAuth, checkDB, checkCache])
  .then(function (results) {
    console.log(results);   // array, IN ORDER: ["Auth Ok","DB Ok","Cache Cleared"]
    console.log("All promises resolved");
  })
  .catch(function (err) {
    console.log("Failed:", err);
  });

Fail-fast behavior

Promise.all([
  Promise.resolve("OK"),
  Promise.reject("DB DOWN"),   // ← this one breaks everything
  Promise.resolve("OK"),
])
  .then(function (r) { console.log(r); })          // never runs
  .catch(function (err) { console.log("Failed:", err); }); // "Failed: DB DOWN"

Flow Diagram

┌─────────────┐ ┌─────────────┐ ┌─────────────┐ │ checkAuth │ │ checkDB │ │ checkCache │ │ (parallel) │ │ (parallel) │ │ (parallel) │ └──────┬──────┘ └──────┬──────┘ └──────┬──────┘ └────────────────┼───────────────┘ ▼ ┌────────────────────────────────┐ │ ALL resolved? │ └──────────────┬─────────────────┘ ┌───────┴───────┐ ▼ ▼ ┌────────────────────┐ ┌────────────────────┐ │ YES │ │ NO — one rejected │ │ .then(results) │ │ .catch(err) │ │ array of values │ │ fail-fast │ └────────────────────┘ └────────────────────┘
Playwright: classic pattern — await Promise.all([page.waitForNavigation(), page.click("a")]) to click a link while waiting for navigation.

6️⃣ Promise.race JS

What is it? Takes an array of promises and settles with the first one to settle — win or lose. Like a real race: only the first finisher matters; the others are ignored.

let fastServer = new Promise(function (resolve) {
  setTimeout(function () { resolve("Fast 100ms"); }, 100);
});

let slowServer = new Promise(function (resolve) {
  setTimeout(function () { resolve("Slow 500ms"); }, 500);
});

Promise.race([fastServer, slowServer]).then(function (winner) {
  console.log("Winner:", winner);  // "Winner: Fast 100ms" (at ~100ms)
});

Flow Diagram

t=0ms fastServer starts ──┐ slowServer starts ──┼──► RACE │ t=100ms fastServer wins ────┘ │ ▼ .then(winner) → "Winner: Fast 100ms" (slowServer's result at t=500ms is IGNORED)
Real use case — timeouts: 
let withTimeout = Promise.race([
  apiCall,                                     // real request
  new Promise(function (_, reject) {
    setTimeout(() => reject("Timeout!"), 5000);
  }),
]);  // if the timeout rejects first → race rejects
Gotcha: race settles on the first settlement — if the first finisher rejects, the race rejects. Use Promise.any if you want the first success only.

7️⃣ All Together — Playwright PLAYWRIGHT

The real E2E login flow — from Callback Hell (Chapter 12) to a clean promise chain (Chapter 13) to async/await (what Playwright actually uses).

Version 1 — Callback Hell

function openBrowser(callback) {
  setTimeout(function () {
    console.log("Step 1 - browser starting...");
    callback();
  }, 500);
}
function clickLogin(callback) {
  setTimeout(function () {
    console.log("Step 2 - login clicked");
    callback();
  }, 500);
}

// Nesting grows to the right — hard to read 😵
openBrowser(function () {
  clickLogin(function () {
    console.log("Test Complete!");
  });
});

Version 2 — Promise chain (flat!)

function openBrowser() {
  return new Promise(function (resolve) {
    setTimeout(() => resolve("browser opened"), 500);
  });
}
function clickLogin() {
  return new Promise(function (resolve) {
    setTimeout(() => resolve("login clicked"), 500);
  });
}

// Returning a promise chains the steps in order ✅
openBrowser()
  .then(function (msg) { console.log("Step 1:", msg); return clickLogin(); })
  .then(function (msg) { console.log("Step 2:", msg); })
  .catch(function (err) { console.log("Error:", err); })
  .finally(function () { console.log("Cleanup done"); });

Version 3 — async/await (what Playwright uses)

// Every Playwright test is an async arrow callback:
// test("login works", async ({ page }) => { ... })

async function loginFlow() {
  await openBrowser();      // pause until resolved
  await clickLogin();
  console.log("Login flow complete!");
}

loginFlow().catch(function (err) {
  console.log("Test failed:", err);
});

8️⃣ Keyword Comparison JS

Keyword What it does Returns Example
Callback Function passed as an argument, called later whatever the outer function returns setTimeout(fn, 1000)
new Promise Creates an async operation with resolve/reject a Promise (pending → fulfilled/rejected) new Promise((res, rej) => ...)
async Marks a function as asynchronous always a Promise async function f() {}
await Pauses an async function until a promise settles the resolved value let data = await api()
Promise.all Runs promises in parallel; waits for all (fail-fast) array of all values (in order) await Promise.all([a, b])
Promise.race Settles with the FIRST promise to settle value/reason of the first finisher Promise.race([api, timeout])
Quick mental model:
  • Callback — "I'll call you back later"
  • new Promise — "I promise a result later (good or bad)"
  • async — "this function deals with promises"
  • await — "wait right here for the result"
  • Promise.all — "wait for everyone"
  • Promise.race — "wait for the fastest"
